**第一道闸门：文件二进制魔数审查与审即粉碎机制**。我们坚决摒弃简单的文件后缀比对，而在二进制层面比对 PNG、JPEG、WebP 真实魔数，阻断伪装成图片的 MZ 或 ELF 脚本可执行攻击。更重要的是，铭牌配方属于商户商业秘密，我们在 OCR 解析完成后，底层立即以零字节物理覆写并调用 `os.unlink` 彻底销毁临时文件，做到真正的‘即审即删、数据零滞留’！

## 三、5 分钟评委高频答辩 Q&A 专项预案

### Q1: “大模型常常存在幻觉，如果它捏造了一条不存在的欧盟法规给商家，导致货物被扣，你们怎么解决？”
> **【回答要点】**: 
> 1. “评委老师切中了法律合规业务的核心痛点。出海易审从根本上**不依赖大模型直接‘背诵’法条**，而是引入了权威法规向量知识库（RAG）。”
> 2. “所有召回的法条均来源于经过法务校验的官方公布文件（如 GPSR 2023/988、2009/48/EC 等）。我们在 System Prompt 中明确加注‘强制溯源约束’，大模型输出的每一条缺陷必须且只能引用 RAG 检索返回的权威条例 ID 与条款原文。”
> 3. “系统还设有双向语义校对，若模型提及的法规编号未命中知识库向量索引，闸门④会直接触发拦截或提示人工复核，从根源杜绝幻觉背书风险。”

---

### Q2: “现场要是突然断网，或者阿里云 DashScope 服务偶发波动超时，系统会不会直接瘫痪卡死？”
> **【回答要点】**: 
> 1. “这是我们在工程架构设计中最重点攻克的高可用课题。出海易审设计了**‘云端真实大模型 + 本地确定性降级规则’高可用双轨制**。”
> 2. “在云端在线状态下，系统由 Qwen-VL-OCR 视觉模型、text-embedding-v3 稠密向量 RAG 与 Qwen-Plus 大模型全链路在线驱动；”
> 3. “当侦测到网络断开、超时或未配置外网密钥时，系统在毫秒级平滑切换至高可用确定性规则降级兜底引擎，依然能够输出标准的缺陷诊断结果；”
> 4. “与此同时，系统严格遵循 **Fail-Closed** 准则，若遭遇不可恢复的异常，系统主动安全阻断并报错，绝不将不可信的错误结果输出给用户。”

### Q3: “很多出海商家的外包装涉及专利设计和未公开配方，把图上传到你们系统，商业机密怎么保障？”

> 2. “当商家上传图片时，文件在内存流中即时处理，提取结构化要素后底层立即覆写并释放原图引用与临时缓冲，服务器磁盘上绝不持久化保留任何客户的原图！”
> 3. “对于结构化诊断数据，数据库关键字段全部采用 **AES-256-GCM** 算法加密，且在 API 层部署了**行级多租户隔离（IDOR 防护）**，商户 A 绝无可能越权获取商户 B 的任何审查报告，跨租户访问 100% 返回 HTTP 403 阻断。”

### Q4: “竞赛要求至少协同 2 种及以上不同类型的 AI 模型，你们具体是如何协同的？各自优势是什么？”
> **【回答要点】**: 
> 1. “我们做到了**三类真实 AI 模型深度协同（Tri-Model Collaboration）**，各自发挥不可替代的优势：”
> 2. “**第一模（视觉多模态 / 感知模型）**：基于阿里云通义千问视觉大模型 Qwen-VL-OCR 与本地视觉定位引擎，专注实体包装图像的图文识别、CE合格标志与WEEE标识结构化定位，将物理视觉信号转化为结构化文字实体；”
> 3. “**第二模（Dense 语义嵌入向量模型 / 认知检索）**：基于阿里云 text-embedding-v3 (1024 维稠密神经向量) 与向量检索库，专注将商户商品类目与欧盟法规建立高维语义空间关联，实现跨语种法规条款的精准召回；”
> 4. “**第三模（通用大语言模型 / 法律推理研判）**：基于阿里云通义千问 Qwen-Plus/Max，专注严谨的法条条款逻辑推理与合规判定，结合前两模提供的事实与法条，生成 Before / After 对比建议并给出整改示范。”
> 5. “三者形成‘视觉感知 $\rightarrow$ 向量认知检索 $\rightarrow$ 决策推理研判’的严密流水线闭环，缺一不可。”
